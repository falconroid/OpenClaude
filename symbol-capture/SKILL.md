# Symbol Capture — 对话中的零摩擦捕获系统

> "温度的半衰期极短——当下不记，感觉就没了。"

## 问题

与 AI 深度对话时，你会同时产生多种输出——
一个 insight 想存下来，一个 TODO 冒出来需要做，一段情绪需要被接住，一个想法值得发布。

正常流程是：等对话结束 → 回忆 → 手动整理。但**温度会凉**。最好的东西在对话流中一闪而过。

## 解决方案

**在对话中用单字符前缀标记内容。** AI 看到前缀，自动路由到正确的位置。

像键盘快捷键——但用于你的思维流。

## 默认符号表

```
!   stream capture     发生了什么 / 值得记录的事件
&   idea               灵感 / 概念 / "灯泡时刻"
=   trick              可复用技巧 / 方法论片段
*   moment             高光对话 / 值得重温的温度
$   publish            发布候选 / 社媒素材
+   todo               待办 / 需要后续执行
?   vent               情绪宣泄 / 先接住再分析
```

1-3 个重复 = priority（`!!!` > `!!` > `!`）。符号可以组合（`*$` = 高光 + 发布候选）。

## 工作原理

用户消息以符号开头时，AI 的行为分两步：

1. **先 capture** — 把内容路由到正确的落盘位置
2. **再分析** — 正常回应对话

这不是 slash command——你不需要记住命令。打到一半时想"这段值得存"，在前面加个 `*` 即可。

## 配置你自己的符号

符号和落盘位置完全可定制。在你的 CLAUDE.md 中定义映射：

```markdown
- `* / ** / ***` → moments 文件（摘要+引用）+ 完整对话存档
- `$ / $$ / $$$` → 发布候选 backlo
- `& / && / &&&` → 灵感登记到 ideas/ 目录
- `+ / ++ / +++` → 任务系统
```

落盘可以是本地文件、Obsidian vault、Notion、飞书——任何你的知识管理系统。

## 设计原则

| 原则 | 说明 |
|------|------|
| **Capture-first** | 先存再回应。符号检测优先于对话分析 |
| **零摩擦** | 一个字符。不需要 /command、不需要菜单、不需要离开对话流 |
| **宁多勿漏** | 假阴性（漏记）的代价远大于假阳性（多记）|
| **温度半衰期** | 当下不记，感觉就没了。符号让 capture 和体验发生在同一瞬间 |
| **写端+读端=系统** | 每个符号同时定义谁写、谁读、触发条件 |

## 符号选择原则

- **避免 markdown 冲突**：`#` 与 heading 冲突，不建议
- **避免 slash command 冲突**：`/` 已被占用
- **避免常见对话用法**：`@` 用于 mention，容易误触发
- **输入法友好**：测试你的输入法是否会转换符号（如中文输入法下 `^` → `…`）
- **语义直觉**：`*` = star/highlight，`$` = value/output，`?` = question/emotion

## 反模式

- ❌ 符号太多（>10 个）记不住 → 从 3-5 个开始，等肌肉记忆形成再加
- ❌ 符号和 markdown 语法冲突 → `##` 是 heading，不是 idea
- ❌ 等对话结束再补记 → 温度已经凉了
- ❌ 每个符号对应一个完全不同的系统 → 符号应该是路由，不是学习负担

## 进化

这套系统从一对用户与 AI 的深度共创中涌现——从 3 个符号（`!` `^` `+`）开始，经过多轮使用、反思、迭代，收敛到 7 个稳定符号。你的符号系统也会进化。从你最需要的 3 个开始。让使用驱动设计。

## 安装

1. 复制 `symbol-capture` skill 到 `~/.claude/skills/symbol-capture/SKILL.md`
2. 复制 `examples/` 到 `~/.claude/skills/symbol-capture/examples/`
3. 从 `examples/claude-md-snippet.md` 复制符号规则到你的 CLAUDE.md
4. 自定义落盘路径为你的知识管理系统
5. 开始使用——在消息中用符号前缀标记内容
